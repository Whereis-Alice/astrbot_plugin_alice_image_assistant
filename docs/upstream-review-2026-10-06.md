这些改进主要提高“搜对图片、正确解释失败、完整交给模型”的可靠性，不会凭空提高搜索引擎本身的命中率。

## 没有照搬的内容

| 项目 | 取舍 |
|---|---|
| 只有用户明确说“搜图”才能调用工具 | 不采用。用户希望 Bot 为图片问题自主查证，继续默认静默检索 |
| 自动忽略表情图片 | 暂不默认加入。表情包也可能是用户正在问的目标；更适合未来在图片列表标注类型、交由明确选图决定 |
| 按用户跨会话冷却、管理员豁免 | 有价值但暂不默认加入，避免阻碍模型补查不同引擎。现有同轮相同检索缓存只减少重复调用，不等同于跨消息限流；公共大群需要时可另加独立配置 |
| Lens `no_cache` | 暂不加入；默认绕过 SerpApi 缓存会增加请求成本，当前没有必须实时刷新同图结果的需求 |
| Lens `safe_search` | 暂未扩展为配置；可作为后续显式过滤选项，不能把它当成现有 Pixiv 内容过滤的替代品 |
| 上游提高到 AstrBot ≥4.25 的兼容基线 | 不直接提升。本插件仍声明 ≥4.16，沿用已验证的消息/工具 API |
| 全量目录重组、替换发送实现、logo、仓库 CI/发包脚本 | 不直接复制。本插件有 Pixiv、文字找图、Yandex、WebUI 与既有生命周期，整体搬运会丢失定制能力；纯目录调整不优先于可验证的功能修复 |

## 发送开关推荐

- `find_image.tool_send_images=true`：文字找图时正常发新图片。
- `reverse_image.ai_behavior.llm_tool_send_results_default=false`：自主分析已发图片时静默查证。
- 反搜工具显式 `send_results=true/false` 覆盖其默认值，手动 `/识图` 正常展示。

## 验证边界

新增回归覆盖实际状态传播、请求次数、URL 配对、等待消费、限量读取与日志内容。测试使用模拟引擎响应；没有上传用户聊天截图到第三方，也没有把测试通过等同于任意原图均能在线识别正确。
